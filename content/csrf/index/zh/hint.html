思路提示

CSRF 的核心是浏览器发请求时自动携带目标站点的 Cookie。本关修改邮箱用的是 GET 请求、无 Token、不校验 Referer，三个条件凑齐就是典型 CSRF。思路：构造一个页面，里面包含指向"修改邮箱"接口的请求（img 标签、自动提交表单、Burp 生成的 PoC 均可），让已登录用户打开这个页面，浏览器就会带着他的 Cookie 自动发请求改邮箱。

详细解题过程（点击展开）
漏洞点：
1. 用 GET 请求执行敏感操作（修改邮箱）
2. 无 CSRF Token
3. 不校验 Referer
利用方式：
方式A - 恶意链接：?newemail=evil@x.com
方式B - img 标签自动请求：<img src="?newemail=evil@x.com"> 嵌在任意网页中，浏览器会自动带 cookie 发请求
方式C - 自动提交表单（POST 型 CSRF 通用模板）：
<form action="" method="get" id="f">
  <input type="hidden" name="newemail" value="evil@x.com">
</form>
<script>document.getElementById('f').submit();</script>
方式D - 使用 Burp Suite 的 CSRF PoC 功能：
在 Burp → Proxy / Repeater 中选中"修改邮箱"的请求，右键 → Engagement tools → Generate CSRF PoC，
勾选 Include auto-submit script，点击 Regenerate 并复制生成的 HTML，保存为 csrf_poc.html，
让已登录的受害者打开该页面，即可自动完成 CSRF 攻击。发送请求前记得开启浏览器的 Intercept 以抓到该请求。
关键：浏览器发请求时自动携带目标站点的 Cookie，这就是 CSRF 的本质。
