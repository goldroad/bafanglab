漏洞描述

上传型 XSS 是存储型 XSS 的一个变种：服务器允许上传 .html、.svg、.pdf 等"会被浏览器解析"的文件，并且上传后的文件可以从同源地址直接访问。攻击者把 JS 写进这些文件，受害者打开链接时脚本就在目标域名下执行，等价于在该站点注入了一段持久化脚本。

漏洞危害

与存储型 XSS 相同：可窃取当前域下的 Cookie / localStorage 会话，冒用受害者身份操作、篡改页面内容、挂马钓鱼。区别在于 payload 藏在文件里而不是数据库里——很多系统只用心过滤了输入框，却完全没管上传文件的内容，因此这条路更难被业务方想到。若上传目录与主站同源，危害与主站 XSS 完全一致。

三种常见载体

  • HTML：.html 以 text/html 返回时浏览器直接解析，<script> 一定执行，最简单也最稳定。
  • SVG：SVG 是 XML 格式的"图片"，但允许 <script> 与 onload 事件。以 image/svg+xml 直接访问时脚本会执行（作为 <img> 引用时不会执行，必须直接导航打开）。
  • PDF：PDF 支持内嵌 JavaScript（/OpenAction + /JS），用 Adobe Reader 打开会弹窗；如果把 PDF 做成语义上的 HTML 混排文件（polyglot），并被服务器错误地以 text/html 返回，浏览器也会执行其中的脚本。

挖掘技巧与经验

  • 凡是"上传 + 回显可访问地址"的功能都要测：头像、附件、工单、简历、导入模板、导出报表。
  • 先看返回的 Content-Type 与响应头 Content-Disposition：inline 且与本域同源 = 高危。
  • 扩展名白名单里有 svg / pdf / xml / html / htm 任意一项，就值得试。
  • 上传目录若在 /uploads/ 这类路径，通常可以直接访问；用目录扫描确认。
  • 成功弹出 alert(1) 只是开始，实战中要证明危害：读取 Cookie、发起同源请求（配合 CSRF）、读取页面中的敏感数据。
