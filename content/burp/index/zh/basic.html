抓包基础

浏览器配置代理转发到本机 8080 端口后，所有的 HTTP 流量都会经过 Burp 代理服务器，并记录在 HTTP History 中（默认不拦截）。如果 GET 请求的参数直接出现在 URL 地址栏中，则不抓包也可以直接修改；反之，URL 地址栏中没有出现的参数（或 POST 请求的参数），必须抓包以后才能看到并修改。

打开拦截开关（Intercept is on）后，浏览器发出的请求会被 Burp 拦截，显示在消息编辑器中：Forward（放行）会把当前拦截的请求发出去，并继续显示下一个被拦截的请求（如果有）；Drop（丢弃）会直接丢弃该 HTTP 消息（服务器不会接收到）；关闭拦截开关，除了会放行当前 HTTP 消息，后续所有的请求都不再拦截。

漏洞描述

垂直越权（参数篡改）：服务端直接信任客户端提交的 role 等身份参数，没有根据会话去数据库查询真实角色，攻击者改包即可提权。

挖掘技巧与经验

  • 拦截所有请求，重点关注 role、is_admin、uid、type、level 等身份字段。
  • 看到 user/admin、0/1、true/false 这类枚举值，先改值再对比响应。
  • 同时测试 Cookie/Header 中的身份标识（如 X-Role、自定义 JWT）。
  • 改包无效时检查是否有签名、时间戳、二次校验等隐藏防护。
