什么是目录扫描

当我们打开一个网站时（例如 www.example.com），并不知道这个网站有哪些目录、文件，或者接口。
例如 www.example.com/abc/def/xyz.php?id=1&name=wuya——注意：/abc/def/xyz.php 有可能是网站根目录下一个真实存在的文件，也可能仅仅是一个映射的接口。

只有收集尽量多的路径、文件、接口，才能有更多的测试点，才可能发现更多的漏洞，包括直接发现各种敏感文件。寻找网站的路径、文件、接口这个过程，就叫目录扫描。

漏洞描述

目录扫描（信息泄露）指站点暴露了未授权访问的敏感目录与文件：数据库备份、隐藏后台、测试文件、编辑器临时文件、版本库等。攻击者据此获取账号密码、源码或直接进入后台，是渗透测试中最常见的第一步。

最常见的敏感文件与目录

扫描字典基本就是按下面这些类别组织的。看到任何一类命中，都要继续往下挖，而不是扫到就结束。

  • 版本控制与备份类：/.git/、/.svn/、/.hg/、/.DS_Store、*.bak / *.old / *.swp / *.zip / *.sql。
    危害：版本库可还原完整源码与全部历史提交，备份文件常含数据库口令、源码甚至整库数据。
    探测要点：先请求 /.git/HEAD，返回 ref: refs/heads/master 即确认泄露；*.php.bak、*.php~ 不会被 PHP 解析，可直接读到原始源码；www.zip、db.sql 要检查是否可下载。
  • 配置文件类：config.php、config.inc.php、.env、web.config、phpinfo.php、info.php、test.php。
    危害：数据库账号密码、云 AK/SK、邮件口令、加密密钥直接外泄；phpinfo.php 会暴露绝对路径、PHP 版本、扩展与已禁用函数，为后续利用铺路。
    探测要点：配置文件通常被 PHP 解析后不输出内容，看到空白 200 不代表不存在，可尝试 config.php.bak、.env（点文件常被服务器直接返回）；phpinfo() 页面特征明显，搜索 PHP Version。
  • 管理后台类：/admin、/admin_area、/manager、/manage、/login.php、/wp-admin、/administrator。
    危害：后台是弱口令爆破、越权、上传 Getshell 的入口，一旦进入往往等于整站失守。
    探测要点：302 跳转到登录页、401 认证框、403 禁止访问都说明路径存在；关注登录页是否有验证码、默认口令、未授权接口。
  • 接口与调试类：/api、/debug、/test、/swagger-ui、/v2/api-docs、/actuator、/graphql、/console。
    危害：接口文档暴露全部参数与内部端点；actuator 的 /env、/heapdump 可直接读取环境变量与内存；Swagger 上的调试接口常可未授权调用。
    探测要点：/swagger-ui.html、/v2/api-docs 返回 JSON 即命中；Spring Boot 检查 /actuator、/actuator/env、/actuator/heapdump。
  • 上传与备份目录：/uploads、/upload、/backup、/bak、/db、/data、/temp。
    危害：上传目录可能允许直接访问已上传的 WebShell；备份目录常直接存放整站压缩包与 SQL 导出。
    探测要点：注意 403（目录存在但禁止浏览）与 301（存在且可访问）的差异；上传目录要看是否可遍历、是否解析脚本。
  • 日志类：*.log、error_log、access.log、debug.log、install.log。
    危害：日志含内网地址、账号、数据库报错 SQL、甚至明文密码；结合 LFI 还可投毒日志 Getshell。
    探测要点：逐个试 error_log、access.log，返回文本即命中；注意大小写与 .txt 变体。
  • 常见 CMS 固定路径：WordPress 的 /wp-admin、/wp-content、/wp-json、/xmlrpc.php；DedeCMS 的 /dede、/data/backupdata；Discuz 的 /uc_server；ThinkPHP 的 /index.php?s= 与 /runtime。
    危害：CMS 固定路径一旦确认，可直接对号入座找已知漏洞、默认后台与备份目录。
    探测要点：先识别指纹（/wp-login.php、/robots.txt、响应头、静态资源路径），再按对应 CMS 的默认字典精准扫描。

挖掘技巧与经验

  • 先用 robots.txt、sitemap.xml、页面报错信息找线索，再看 JS 文件里硬编码的接口路径。
  • 关注响应码差异：200（存在）、301/302（重定向）、403（存在但禁止）、404（不存在）；很多站点自定义了 404 页面，要靠响应长度判断。
  • 大字典扫不到时，换思路：递归扫描已发现目录、用 404 页面大小做过滤、加 --random-agent 绕过简单 WAF。
  • 扫到 /.git/ 必深挖：先验证 /.git/HEAD 是否返回 ref: refs/heads/...，再用 GitHack/git-dumper 拖下整个仓库还原源码与历史。

.git 信息泄露专题

  • 成因：用 git 部署/备份站点时把 .git 目录一起上传到 Web 目录，且服务器未禁止访问。
  • 关键文件：.git/HEAD（当前分支）、.git/config（仓库配置）、.git/logs/HEAD（明文提交记录，浏览器/Burp 可直接读）、.git/index（暂存区清单）、.git/objects/（zlib 压缩的 blob/tree/commit 对象）。
  • 工具利用：GitHack、git-dumper 下载整个 .git 后 git log、git checkout、git show 还原全部源码。
  • 手工利用：读 logs/HEAD 拿提交 sha1 → 按"前 2 位 / 后 38 位"拼 objects/ 路径下载 → zlib 解压即得对象内容（commit→tree→blob 逐级解析）。
  • 重点认知：文件在最新版本被删除不等于安全——历史提交仍可还原。泄密后应改密码并从历史中彻底抹除（filter-branch / BFG）。
