思路提示

目录扫描的核心是通过 HTTP 状态码差异判断路径是否存在。思路：先用工具（dirsearch / ffuf）挂上字典批量探测，再根据返回的状态码判断哪些路径有东西。重点关注 301（目录存在，自动补斜杠）、403（路径存在但禁止访问）、200（直接访问到内容）。本关藏了若干敏感文件，包括 .git 仓库、编辑器残留 .bak 等，逐个找到它们。

详细解题过程（点击展开）
推荐工具：
dirsearch -u / -e php,txt,sql,zip,bak
ffuf -u /FUZZ -w dict_dirs.txt
字典关键字：backup、admin、admin_area、test、uploads、robots.txt、install.php、config、config.php.bak、.git
现成字典：本页上方可下载 dict_dirs.txt，内含全部目标路径，可直接用作扫描字典。
线索：先看 /robots.txt，Disallow 里往往写着敏感目录。
目标5 - 编辑器残留泄露（config.php.bak）：
IDE（VS Code / PHPStorm / Vim）在崩溃恢复或定时备份时会自动生成 .bak / .old / ~ 文件。
这些文件不会被 PHP 解析，直接返回原始源码。关注文件名模式 *.php.bak、*.php~、*.bak。
目标6 - 响应码识别速记：
• 301 = 路径是个目录，浏览器自动补斜杠 → 路径存在
• 403 = 路径存在但禁止访问（目录浏览关闭 / .git / .htaccess 被保护）
• 404 = 不存在；本靶场 phpStudy 环境的 404 页固定约 2659 字节（其他环境的 404 页大小不同，以 Content-Length 为准）
目标4 - .git 信息泄露（backup/.git）：
1. 浏览器访问 /backup/.git/HEAD，返回 ref: refs/heads/master 即确认泄露
2. 访问 /backup/.git/logs/HEAD 看明文提交记录（若浏览器下载/乱码，用 Burp 查看或另存后按 UTF-8 打开）
3. 注意最后一次提交叫"删除敏感文件"——但历史还在！
4. 用 GitHack / git-dumper 拖下整个仓库，然后：
git --git-dir=.git log --oneline
git --git-dir=.git show HEAD~1:secret.txt → 拿到通关凭证
git --git-dir=.git show HEAD~2:db_config.php → 拿到开发库口令
5. 纯手工玩法：从 logs/HEAD 取提交 sha1，按 objects/前2位/后38位 下载对象，zlib 解压后按 commit→tree→blob 逐级解析出文件内容。
