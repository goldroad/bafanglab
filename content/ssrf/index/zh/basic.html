漏洞描述

SSRF（服务器端请求伪造）指服务端根据用户提供的 URL 发起请求，且未限制目标地址，攻击者可借此访问内网服务、读取本地文件、探测端口，甚至深入内网横向（打 Redis、MySQL、云元数据接口）。

漏洞危害

SSRF 把服务器变成攻击者的"内网跳板"：可探测并攻击公网本不可达的内网系统（数据库、Redis、ES、管理后台），常常一击打穿整个内网；云环境中访问 169.254.169.254 元数据接口可窃取临时凭证，接管云账号下所有资源；配合 file://、gopher:// 等协议还能读取本地文件、直接攻击内网服务，危害远超普通 Web 漏洞。

挖掘技巧与经验

  • 常见功能点：图片/文件下载、网页快照、URL 预览、导出、Webhook、代理接口、PDF 生成。
  • 先测协议：file://、http://、dict://、gopher://；再看能否访问 127.0.0.1 与外网。
  • 内网探测：用 Burp Intruder 爆端口，观察响应码/长度/耗时差异；也可用 http://127.0.0.1:3306 看 MySQL 握手包。
  • 有过滤时尝试绕过：127.0.0.1 的变形（0.0.0.0、localhost、[::]、127.1）、URL 编码、@ 与 # 截断、302 跳转绕过。
  • 云环境优先探测元数据地址（如 169.254.169.254），往往能拿到临时凭证。
