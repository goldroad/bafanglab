漏洞描述

SQL 注入指程序把用户输入直接拼接进 SQL 语句，导致攻击者可以改变查询语义、读取任意表数据，甚至执行系统命令。本关为数字型 GET 注入：WHERE id = $id，参数前后没有引号包裹。

漏洞危害

SQL 注入是危害最严重的 Web 漏洞之一：攻击者可拖取整库数据（用户、订单、支付信息），酿成千万级数据泄露事件；可构造语句绕过登录直进后台；权限较高时还能读写服务器文件（into outfile）植入 WebShell，甚至借 xp_cmdshell 执行系统命令拿下整台服务器。大量真实数据泄露事件的源头只是一处 SQL 注入。

挖掘技巧与经验

  • 分类判断：数字型用 and 1=1 / and 1=2；字符型先用 ' 看是否报错，再 and 1=1' 。
  • 标准流程：判注入 → order by 猜字段数 → union select 找显示位 → 爆库表列 → 取数据。
  • 页面无回显时考虑报错注入（updatexml/extractvalue）、布尔盲注、时间盲注。
  • 实战中注意 WAF：注释符变形 /**/、大小写混写、union%0aselect 换行、URL 二次编码。
  • sqlmap 能自动跑，但建议先手工跑通一遍，理解每种 payload 的返回差异。
