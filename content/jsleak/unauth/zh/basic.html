漏洞描述

未授权访问（Broken Access Control，越权访问）指接口没有校验"调用者是谁、能不能做这件事"，只在前端页面上做了登录与权限判断。攻击者跳过页面，直接用浏览器或 Burp 请求后端接口，就能拿到本应登录后才能看到的数据，甚至执行管理操作。OWASP Top 10 把它排在 A01 位。

常见成因

  • 只在页面做校验：登录、权限判断都写在前端 JS 里，后端接口完全裸奔。
  • 缺少统一鉴权中间件：每个接口各自实现（甚至忘了实现）鉴权，新增接口最容易漏。
  • 信任前端传来的身份：接口直接使用 uid、role、isAdmin 等参数，改个值就变成别人。
  • 靠"地址隐蔽"当保护：认为用户不知道 /api/ 路径就安全，而路径往往写在 JS、sourcemap 或接口文档里。
  • 内部接口暴露公网：员工、订单、配置等内部接口直接对外可访问，没有网关或 IP 白名单。

漏洞危害

未授权访问直接击穿权限边界：没有任何账号的攻击者可以批量导出员工通讯录、手机号、身份证、订单等敏感数据，造成大规模隐私泄露与合规处罚；暴露的管理接口还能创建管理员、改配置、删数据，等于后台被完全接管；水平越权常被用于薅羊毛、改订单金额，造成直接资金损失。接口可被脚本批量调用时，损失会被成倍放大。

如何在浏览器 / Burp 中验证

  • 浏览器：F12 → Network 观察页面发出的 XHR 请求；或直接在地址栏打开接口 URL（建议用无痕窗口，确保没有登录态 cookie）。
  • Burp：Proxy 抓到正常请求 → 右键 Send to Repeater → 删除 Cookie、Authorization、token 等身份头 → 发送，若仍返回数据，说明该接口没有鉴权。
  • 横向越权：把请求里的 uid / id / orderId 换成别人的值，能拿到别人的数据即越权。
  • 纵向越权：用普通账号的凭证调用管理员接口，能成功即提权。
  • 接口发现：翻前端 JS / sourcemap 找 api、internal、userList 等关键字，或对 /api/ 做目录扫描。

本关利用路径

本关是一个"内部员工中心"：前台登录页无论输入什么都会失败，它的作用只是提示你"前端做了校验"。真正的数据接口是 {{BASE}}/modules/jsleak/api/users.php，它没有 session_start()、没有任何 token 校验，直接输出全部员工记录。在前端资源 app.js 的 API_ROUTES 中可以看到这个路由。

直接用浏览器打开该接口（不登录、不带 cookie），返回的 JSON 中 data[0] 就是 admin，remark 字段里写着通关凭证。

修复思路

  • 所有接口统一走鉴权中间件，默认要求登录，未登录返回 401。
  • 敏感接口再做角色与数据归属校验（管理员才可看员工列表），拒绝时返回 403。
  • 对象级鉴权（防 IDOR）：按 uid/orderId 取数据前先确认归属当前用户。
  • 返回字段最小化：手机号、邮箱、内部备注按需脱敏或裁剪，不把整行数据丢给前端。
  • 内部接口不暴露公网，配合网关、IP 白名单、限流与访问日志。
